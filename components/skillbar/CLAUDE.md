# components/skillbar: HP/MP regen clock, what the HP/MP went on, casts left, the skill bar

A movable hotbar-style strip over the game: MP/HP regen wheels (tick size, seconds to the next tick),
and every skill with an MP cost with the casts your MP allows. The tracker side measures; the helper
draws. It owns the live.json sections `hp mp regen skills usage` and the `usage` service.

**Memory (local):** `.claude/handoff/components/skillbar.md`: read it before changing anything here.
**May import:** `hub`, `gamedata`, `base`. **Never:** another component, `engine`, `launcher`.

## Files
| File | Role |
|---|---|
| `component.py` | `SkillbarComponent`: builds the `Feed` on `service_start`, provides `usage`, publishes the 5 sections; `ui(shell)` for the bar |
| `feed.py` | `Feed`: one `Meter` per HP/MP, `mpuse.Usage`, the per-character `RegenModel`, `burst_looks` (regen clock bursts), the five `section_*` functions, `cast_extras`, `history/usage/<date>.csv` log |
| `meter.py` | `Meter` (regen clock: tick size, period, phase, sticky checks), `regen_settings()`, `REGEN_DEFAULTS`. Pure model, no pixels |
| `mpuse.py` | `Usage`: explains every HP/MP change (regen tick, casts by cost, potions x item bonus, Magic Guard, MP Eater, Heal, Recovery, level-up, death; unexplained = kind `other`). `python -m components.skillbar.mpuse LOG.csv [id=level ...]` replays a recording |
| `maxwatch.py` | `MaxWatch` (per hp/mp): HUD max vs the stored base; a max buff (`BUFF_SKILLS` = Hyper Body 1311005, levels from `skills_classic.json`) is not a new base; a lasting difference (5 same looks or right after a level-up) is: returned to the feed, stored by `Profile.learn_base_max` |
| `regen.py` | `RegenModel`: tick sizes (math in `gamedata/formulas.py`) from max MP + Improved MP Recovery text, learned extras per character (`characters.json "regen"`) |
| `partyfx.py` | Pure (no tkinter): `credit_heals` (Cleric-side Heal credit), `PARTY_SKILLS` (skill id -> name, caster jobs, kind `heal`/`buff`, usage event name, `icon` = state from the buff list; Heal 2301001 Cleric/Priest/Bishop event `Heal (party?)`, **Haste 4101001** Assassin/Hermit/Night Lord and **4201001** Bandit/Chief Bandit/Shadower (`same_as` 4101001: same picture, ONE slot keyed and hidden as `party:4101001`), kind buff, `icon` True, level 7 assumed (160 s: the player's Haste from a party member gave Speed +16 = level 7)), `speed(sid, level)` (the text's "Speed +N": the Haste slot's caption is `+16` with the boot mark, `~+16` while the level is assumed; the caster names move to its right-click menu "From ..."), `levels_in` / `level_for_duration` / `casters(party, sid, now)`, `party_slots(party.json, usage.recent, now, my_map, buffs=usage.party_buffs)` (slot `on`, `est`, `ends`, `level`, `lvl_src`; an `icon` entry also gets a slot **whenever its icon shows, with no party link / no caster in it**: caption = the caster when party.json has exactly one, else "Haste"; a caster in the party but no icon = dim slot; nothing known and no icon = no slot), `DEMO_BUFF` (Haste, demo only: event driven). Add a party skill = one table entry |
| `skillicons.py` | Skill pictures downloaded once from MeowDB (`classes/icons/<7-digit id>.png`) into `<data>/assets/skill_icons/`, modeled on `training/itemicons.py`: `path(sid)` = local PNG or None (+ background fetch if `internet.allowed("skillicons")`), `index.json` fetched/failed, retry after a day. Used by `skillbar_ui._skill_pic` only when there is no cut of my own |
| `skillbar_ui.py` | `SkillBar` (helper): draws at ~10 fps, reads live.json once a second; hidden when live.json is > 6 s old; `--demo`; after my skills a wider gap + divider, then the party slots |
| `__init__.py` | docstring only |

## Interfaces
- **Listens to (events):** `service_start` (build feed, provide, publish, `hub.on_idle(feed.burst_looks)`); `facts_begin` (`prof`, `now`: another character starts everything over); `fact` (`t, kind, value, prof`; kinds used: `vitals` {hp, mp: [cur, max]}, `buffs` {on: [skill ids], left?: {id: seconds}, mins?: {id: n}} (icons showing at the top right; `left` = big countdown digits of a party buff, `mins` = its small minutes digit; both are missing until the engine has learned the digit shapes into `glyphs_buff.json`, ~20 s into the first last minute it sees: the estimate path (`est`, `~`) carries the slot until then), `away` (resets the regen clocks), `party` (row count -> usage party flag)).
- **Emits:** nothing. **Hooks `relay_post`** (party link thread, defined by the party component): `extra["healed"] = [seq, last, avg]` (ints) when a party Heal has landed on me (`Feed.party_heal_post`, a tuple the tracker thread replaces whole; the hook only reads it), and `extra["_fast"] = True` once per new seq so the next post follows in 1 s instead of 3. Works in v1 (flat body) and v2 (presence field) as is.
- **Provides / asks (services):** provides `usage` (the current `mpuse.Usage`; replaced when another character plays). Asks `mp_price` and `price_of` (training) for the skills list.
- **Source hooks used:** `hub.source.watch_buffs(ids, folder=)` (owned buff-kind skills with an icon file, plus the partyfx `icon` buffs (`Feed._party_ids`) **while the party box has other members** (`party_n` > 1), pictures from `skillicons.folder()`, fetched with `skillicons.path(sid)`; re-sent when either list changes, checked at every live.json beat), `hub.source.boost(fps, seconds)`, `hub.source.quick_vitals(t)`, `hub.take_facts()` (in `burst_looks`). The HP/MP numbers come from the engine via the `vitals` fact (reader `engine/vitals.py`).
- **Settings:** `skillbar` {enabled, locked, x, y (shared), `chars` {fingerprint: {hidden [skill ids], show: casts|mp|mesos, guard_show: ehp|absorb|last}} (per character; fingerprint = live.json `who`; a character with no entry gets the defaults, nothing hidden, so beginner skills hidden on one character don't hide on a new one); top-level hidden/show/guard_show = fallback only when `who` is null (--demo, old live.json). Accessors `char_cfg` / `char_put` / `migrate` (pure, module level in `skillbar_ui.py`). **Migration** (once, at bar start): `chars` empty and top-level values not default -> moved into the highest-level character of `history/characters.json`; skipped if the file is missing or has no levels (retried next start). Old top-level keys are left as they are}; `regen_check` {min_ticks, max_ticks, step, burst_fps, pad_s} (read by `meter.regen_settings()`; its Settings > General row lives in `hub/settings_ui.py`). DEFAULTS in `hub/helper_settings.py`.
- **Writes (data folder):** live.json sections, published in this order (the regen section sets a meter's `prior` that hp's state shows): `mp`, `skills`, `regen`, `hp`, `usage`. `hp`/`mp` = `{cur, max, tick, period, next, sure_s, ticks_seen, clock, check_every, checks, restarts, ... , base_max (stored base), buff ({id, name, pct, ends} or null), predicted (bool: the tick shown is from math, no tick seen yet), predicted_from ("stored" before the first HUD read, "hud" after, null)}`; `regen` = `{mp|hp: {skill, level, says, icon}}`; `skills` = `[{id, name, level, max, mp, casts, mesos, mesos_with, items, meso_varies, icon, guard}]` (`guard` only on Magic Guard 2001000: `{pct, absorb, ehp, last, last_t}`; every entry also has `kind` (skill kinds file), `hp_cost`, `active` (buff icon showing: true/false; null = not watched or not seen yet), `attacks` (Heal: "undead"), `eater` (MP Eater 2100000/2200000/2300000 only, listed although it costs no MP: `{last, t}` = the last absorb, kept in the regen record `"eater"`; its slot shows `+N` under it with a blue cross and pulses on a new absorb; mpuse books MP Eater only with an attack in the same look (pen 1.2) or within `EATER_AFTER_S` 1.5 s after one), `heal` (Heal only: `{avg, recent, n, level}` from own Heal rises that did not end at max HP, null until one; stored per Heal level in the character's regen record under `"heal"` as `{level: {n, sum, min, max, recent[30], last_t}}`; its slot shows `~avg` / `?` under it with a cross mark), `recovery` (Recovery 0001001 only: `{tick, t, ticks, first, every, n, cd}` = HP per tick at its level, the last cast while its ticks or cooldown run (else null), ticks booked since, cooldown s from the cast (skill data `cd`); `skillbar_ui._recovery_next` -> phase heal: one sweep per tick (first 5.9 s after the cast, then every 5.1 s, re-synced on each booked tick) with seconds to the next tick, a red flash on each tick and `+tick` under it (red cross); phase cd: after the last tick, a sweep of the rest of the cooldown with its seconds (whole seconds, also over 100), no caption), `nimble` (Nimble Feet 0001002 only: `{t, dur, cd, speed}` = the last cast while the buff or cooldown runs (else null; `Usage.last_cast`, also set when its watched buff icon comes on > `BUFF_CAST_S` 3 s after a booked cast), buff time / cooldown s at its level (skill data `time` / `cd`), the text's "speed +N"; `skillbar_ui._timer_next` -> phase on: sweep + seconds, a green flash every second, `+speed` under it with a boot mark; phase cd: sweep of the rest of the cooldown, no caption), `cast_n` (casts seen: an attack's slot, or one with `attacks`, pulses for `PULSE_S` when it goes up, blue = MP cost, red = HP, both = two rings); its slot shows one of them as a caption under the slot instead of casts (captions carry a tiny code-drawn mark: clock = regen, shield = Magic Guard, cross = Heal / Recovery, boot = Nimble Feet (pixel art `BOOT_PIXELS`, 1.5x the other marks); `skillbar_ui.MARKS`). Sweeps: gold `SWEEP_TICK` = time to the next tick or while a buff runs (MP/HP regen, Recovery ticks, Nimble Feet on), dark `SWEEP_CD` = a cooldown (MP Eater, Recovery / Nimble Feet after, party buffs), ehp red, MP numbers blue; `skillbar.guard_show` ehp|absorb|last, right-click); `usage` = `{since, hp, mp, recent, levels_seen, party_heal, party_buffs}` (`party_buffs` = `{party buff id: {since, ends, est, mins, level, src}}` (one id per picture: only 4101001; `level` = the Haste level behind the estimate, `src` = `learned` (this caster's stored level) / `range` (middle candidate of the minutes digit read at the cast) / `assumed` (7)) for the watched party buff icons showing now (ids absent = icon not seen / not in a party): `since` = when the icon was first seen (epoch s, the fact's time; a restart of the app mid-buff makes it late), `ends` = epoch s of the end, best source first (`Feed._party_buff`): the big digits (`buffs` fact `left`, exact, last 60 s), the small minutes digit going n+1 -> n between two facts (= 60(n+1) s left right there, within a second; `est` false), else an estimate `since + duration_s` at the entry's level (`est` true) kept inside the minutes digit's range (re-anchored to the middle of the range on the first mismatch); `mins` = the last minutes digit read (a digit = n*60 .. n*60+59 s left); a recast shows as the minutes digit going up, a minutes digit after a < 60 s read, or the digits missing; **Haste level learning** (`Feed._party_cast / _party_range / _party_learn`): a FRESH cast (the icon came on after being seen off in this watch for at least `PARTY_OFF_S` 3 s: a shorter gap is a missed look, which would otherwise teach a wrong level from the time left, or a recast shown by the minutes digit) has `t0`; the minutes digit m read within `PARTY_M0_S` 3 s of it limits the duration to [60m, 60m+59] (levels from the table: the stored/assumed level if it fits, else the middle candidate); when the exact end is known (big digits or the 2 -> 1 sync) duration = end - t0 is snapped to the nearest table duration, only within `PARTY_LEVEL_TOL` +-4 s (10 s steps: 165 stays unknown, 166 reads as 170) and inside m's range, and stored in the character's regen record `party_levels` `{"4101001": {"<caster name or ?>": {level, t}}}` (name only when party.json has exactly one caster of the jobs); the next cast starts from it. A buff already showing when watching starts, or a digits-missing recast, has no t0 and learns nothing. Right-click the Haste slot: disabled line `Haste Lv 7 (160 s, learned|assumed)`. digits missing for `PARTY_MISS` 4 facts in a row while more than `PARTY_RECAST_S` 3 s were left = cast again as well: `since` restarts, the estimate starts over; `party_heal` = `{avg, n, last, last_t, seq}` of the party Heals that landed on me, from the regen record `"party_heal"` `{seq, n, sum, min, max, recent[30], last, last_t}` (seq counts capped ones too; the rest only uncapped; not per level) or null until one; `Heal (party?)` events now carry `to_full` like own Heal). Readers: `skillbar_ui` (hp, mp, regen, skills), training (via the `usage` service); `usage` is also in live.json for study. Also `live_casts.json` `{t, n: {skill id: casts}}`, written the moment a cast is booked; the bar checks it every 100 ms so the attack pulse comes ~0.2-0.4 s after the cast (live.json alone: up to ~2.4 s). After a cast, `burst_looks` keeps looking at HP/MP `COMBAT_FPS` (5) times a second for `COMBAT_S` (5 s) (`Feed.in_combat`). Also `history/usage/<date>.csv` (time, meter, kind, name, amount, skill, level) and the character's `regen` record in `history/characters.json` (through `prof.save_regen`, clock saved every 10 s, picked up again within 90 s).
- **Predict first (login):** `Feed.begin` runs `_predict` as soon as `prof.who` is set (Profile keeps `current` in characters.json, so it is the last-played character at once): `Meter.known` from stored `mp_max` + stored skill levels, before any HUD read; `_expect` then reconciles with the HUD max. `Profile.learn_base_max(kind, value, t, source)` stores a lasting HUD max; a Stat window read replaces it.
- **Math:** all of it lives in `gamedata/formulas.py` (see `STATUS` there for verified / measured / guess); `regen.py` and `mpuse.py` call it.
- **Reads (shipped data):** `paths.asset("gamedata/skills_classic.json")` (names, `mp` per level, `levels` texts), `gamedata/potions_classic.json` (in mpuse). Data folder: `templates/skill_icons/<id>.png` (cut from the player's own Skill window; local only, never shipped; the engine buff watch uses only these). Picture order on the bar: own cut, else `assets/skill_icons/<id>.png` (downloaded, below), else initials.
- **Writes / internet:** `<data>/assets/skill_icons/` (`<id>.png` + `index.json`) via `skillicons.py`; internet feature `skillicons` ("Skill pictures", meowdb.com, default on). Nexon art: local only, never sent through the relay.
- **Party group (helper only):** `skillbar_ui` also reads the data folder's `party.json` (party link; others only, stale = `ok` false or `t` > 30 s) and `status.json` (`map`) once a second with live.json, and `live.json usage.recent` events. `partyfx.party_slots` gives one slot per `PARTY_SKILLS` entry with a caster of that job in the party (dim = none on my map). Heal: green pulse when a new `Heal (party?)` event arrives, `+amount` caption (cross mark) for 15 s, else `~avg` (cross, from live.json `usage.party_heal.avg`) when one exists, else the caster names. **Cleric side:** when my own skills list has Heal (2301001), `skillbar_ui._credit` runs `partyfx.credit_heals(state, party.json members, my Heal cast times, now)` once a second: the cast times are when `cast_n` of Heal went up (live_casts.json, the attack-pulse path); a member's `healed` seq (party.json, sent by their bar) going up within `HEAL_CREDIT_S` (12 s) after my cast credits `{name, amount, avg, t, cast_t}`. My own Heal slot shows green `+TOTAL` (sum for the newest cast, cross mark, `CREDIT_COLOR`) with a green pulse for `RECEIVED_S` after a credit, else the usual `~avg`; its right-click menu lists disabled lines `Bob +132 (avg ~130)` for the last 3 casts, newest first. Attribution limits: NOTES 2026-11-07. Check: `python dev/partyheal_sim.py` (in release_check). Buff kind: sweep + seconds left, caption = caster. Entries with `icon` (real Haste): lit while `party_buffs` has the id, exact seconds from `ends`, else an **estimate** (the seconds show as `~143` and the caption as `~Name`; `est` from live.json); an estimate that ran out while the icon still shows = lit with no number; no icon = dim; pulse on a new `since`. Other buff entries (demo): from the event time + `duration_s`. Each party slot has a 40 % white "users" watermark (`_mark_users(size, color)`, code-drawn; artist art can replace it). Hide: right-click, stored as `"party:<id>"` in the character's `chars[who].hidden`. `--demo` fakes FakeCleric (Heal every 8 s) and FakeSin (Haste level 5, 140 s countdown, restarts at 0); fakes exist only in the demo path (`_demo_party`).
- **Helper side (`ui(shell)`):** `PanelHost(shell, "skillbar", "skill bar", make_bar, dy=400)`; menu "Skill bar" + "Lock skill bar (click-through)"; Settings > General extra (order 10); right-click a slot: lock/hide, corner (casts / MP / mesos), remove / add back a skill; hide / corner / guard number are saved for the current character only; `on_settings_save` keeps x, y, locked, chars; right-click Magic Guard: its number (ehp / absorb / last).

- **Ambiguous casts (buff icon):** a cast mpuse booked as an attack whose MP cost an owned, watched buff shares (Energy Bolt / Magic Guard, 8 MP) is booked provisionally (mpuse keeps its tie rule, so the replay CLI is unchanged) but parked in `Feed.pending`: not in the usage CSV, not in `live_casts.json` / `cast_n` (`Feed.shown_counts`). Decided by the `buffs` facts: that buff's icon flips (either way) from `FLIP_BEFORE_S` (0.3 s) before to `HOLD_S` (1.0 s) after the MP drop -> `Usage.rebook` moves the cast to the buff (counts, totals, event); `HOLD_S + SETTLE_S` (1.4 s) without a flip -> the attack stands. Only when the buff's state is known (a `buffs` fact arrived), else no waiting. Off with no MP drop: state only.

## Out of scope / don't read
`engine/vitals.py` internals (digit templates `glyphs_hud.json`), `hub/character.py` (Profile), training and party code.

## Rules that bite here
- Passive screen reading only; skill icons are Nexon art: local, never shipped or committed.
- Per-frame work goes in `perf.timed("name")` (burst looks do).
- Changed regen? Validate per level locally with `dev/vitals_log.py` against `skills_classic.json` before trusting the bar.
